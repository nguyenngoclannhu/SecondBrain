So for this week’s Frontier issue, I ran a live session with Frontier members to walk through Mistral 3. 

It’s the perfect opportunity to do something special: showing one method I use to study frontier model architectures myself, and connecting this new model to concepts we’ve already explored in the Frontier series.

When a new frontier model comes out—especially when there are no papers or blog posts available yet—one method I use is to start with the Hugging Face repository itself. I treat the files the model ships with as the ground truth and try to reconstruct the architecture directly from them. 

By reading configuration files and inspecting weight names and shapes, I map numbers back onto an architecture blueprint by hand. The goal isn’t to reverse-engineer everything perfectly, but to build intuition—learning how much you can understand about a model just from the artifacts it leaves behind.

In this live session, we started with going through `safetensor.index.json` and see to what extend we can reverse-engineer the architecture just from the weight names and shapes in this file alone.

Then we dove into `params.json`, unpacking each parameter and matching the numbers back to the underlying architecture blueprint.

<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">So for this week’s Frontier issue, I ran a live session with Frontier members to walk through Mistral 3. </p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">It’s the perfect opportunity to do something special: showing one method I use to study frontier model architectures myself, and connecting this new model to concepts we’ve already explored in the Frontier series.</p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">When a new frontier model comes out—especially when there are no papers or blog posts available yet—one method I use is to start with the Hugging Face repository itself. I treat the files the model ships with as the ground truth and try to reconstruct the architecture directly from them. </p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">By reading configuration files and inspecting weight names and shapes, I map numbers back onto an architecture blueprint by hand. The goal isn’t to reverse-engineer everything perfectly, but to build intuition—learning how much you can understand about a model just from the artifacts it leaves behind.</p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>In this live session, we started with going through </span><code>safetensor.index.json</code><span> and see to what extend we can reverse-engineer the architecture just from the weight names and shapes in this file alone.</span></p>
