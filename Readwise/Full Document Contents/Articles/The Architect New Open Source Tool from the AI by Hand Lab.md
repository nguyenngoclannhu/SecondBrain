I want to share with you the first functional prototype of **Architect**—a new open source tool created by Jubair, my PhD student, to generate *AI by Hand* neural network architecture blueprints directly from an Excel workbook.

#### Introduction

(written by Jubair)

Hi there,

Thank you for your interest in **Architect**! I’ve been working on this for a long time, and this prototype is implemented entirely within a single Excel workbook.

When you open the workbook, you will see two tabs: the **Architect** tab and the **Blueprint** tab.

For years, Prof. Tom Yeh, my PhD advisor, has been building numerous Excel **Blueprints** of deep learning architectures entirely by hand. He also forced me and many others students to build blueprints by hand in classes and research projects.

I have had enough. So I decided to threaten Prof. Yeh’s job by creating the **Architect**, a tool that can automatically generate new blueprints. 😉

###### Input (Architect)

Think of the **Architect tab** as a planning table. Instead of writing code, you describe your model step by step, one row at a time. Each row answers three basic questions: *What is the input? What operation should happen? What should come out?*

The **Input column** is where tensors are defined. In this example:

```
`X = Rand, feat = 6, batch = 10` 
```
It means: create a random input tensor with 6 features and 10 batch elements—we give it a name `X`. You don’t need to worry about arrays or indexing—Excel handles that for you.

The **Ops column** describes what to do with that input. You can write—

```
`Linear`
```
which means applying a standard linear layer (a matrix multiplication plus bias). This is the same operation used in most neural networks, just written in a human-readable way. In the current version `(V1)` available operations are: `Linear`, `ReLU` and `Softmax`.

The **Output column** records what you expect after the operation. We give—

```
`X, dim = 5`
```
and it tells The Architect that the Linear layer should map the 6 input features down to 5 output features, producing a new tensor. This will be stored as a variable `X`.

[![](https://substackcdn.com/image/fetch/$s_!I0Wd!,w_1100,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Fccc7588a-0cc6-4adb-80f0-3b08c94506aa_3478x2433.png)](https://substack.com/redirect/07822848-f44b-4642-bc2d-72d239972b86?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI_zv_M4N2A50pyRXMoP1g)Fig 1: The Architect Tab###### Output (Blueprint)

Once you click **Run** in the Architect tab, the design is expanded into the **Blueprint** (see Fig-2). This is where the abstract description turns into something concrete and explorable.

At the top of the Blueprint, you see the **input tensor** laid out as a grid. Each **row represents a feature**, and each **column represents a batch element**. This makes the shape of the data immediately visible, without needing to read tensor notation or code.

Below that, each operation is unfolded into its full computation. For a Linear layer, the Blueprint shows the **weight matrix**, the **input tensor**, and the resulting **output tensor**, along with the exact math (`X₀ = W₀X + b₀`). Every number you see is backed by an **Excel formula**, so nothing is static or precomputed. You can change a value and watch the effect propagate through the network.

On the right side, the **Code panel** shows the matching **PyTorch code**, generated layer by layer. This lets you directly connect what you see in the Blueprint with how the same model would be written in practice. The visual blocks and the code blocks stay aligned, making it easy to cross-check understanding.

[![](https://substackcdn.com/image/fetch/$s_!aXp_!,w_1100,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Ff178d308-ea83-47dd-9a17-e252f148deb0_2048x1340.png)](https://substack.com/redirect/6e004c1d-073c-45e3-afbb-0ad3825b7c11?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI_zv_M4N2A50pyRXMoP1g)Fig 2: The Blueprint TabThe Blueprint tab allows you to trace how data flows, how shapes change, and how math turns inputs into outputs. Instead of treating neural networks as black boxes, the Blueprint turns them into something you can read, inspect, and reason about—one layer at a time.

#### Design Philosophy

I designed and developed the Architect with a few core requirements that prioritize clarity, familiarity, and learning by doing.

###### **1. Use Excel as the native environment.**

Excel is already widely known and easy to use. Most users do not need to learn a new interface, language, or tool before they can start exploring neural networks. By running entirely in Excel, the system removes onboarding friction and lets users focus on understanding the model rather than the software.

The Architect is implemented using **Office Scripts**, which currently run within **Microsoft 365 Academic accounts**. This means access to an educational Office 365 license is needed to use the system in its current form. For many students and educators, this is already part of their existing setup.

###### **2. Make tensor shapes and dimensions visible at all times.**

Tensor shapes and dimensions must be explicitly shown and easy to track throughout the network. The layout follows a consistent pattern: weights are always placed on the left, and columns consistently represent the batch dimension. This stable visual structure helps users follow the data flow without mentally reconstructing shapes.

###### **3. Reveal the math behind every operation.**

Each layer exposes its underlying mathematical operation rather than hiding it behind a function name. Combining mathematical formulas with concrete tensors and numbers creates a unique learning experience where users can directly connect equations to actual values.

###### **4. Link visualization directly to PyTorch code.**

For every visual block, the system provides the corresponding PyTorch code. This allows users to verify the math, tensor operations, and implementation side by side. Seeing the visualization, formulas, and code together makes the overall process easier to understand and trust.

###### **5. Represent tensor values using Excel formulas, not fixed numbers.**

Tensor entries are expressed as Excel formulas rather than static values. This gives users the freedom to modify inputs, weights, or operations and immediately observe how changes propagate. Users can experiment, play, and align spreadsheet formulas with mathematical expressions in a natural and flexible way.

#### Feature Roadmap

Here’s a roadmap of the features I’m working on adding to the **Architect**. I plan to release updates regularly, as outlined below:

1. **Foundations (Available now)**  
Random Input, Linear, ReLU, and Softmax.  
Learn how tensors flow through a network and how raw values turn into probabilities.  
👉 This is the version covered in the current post.
2. **Better Nonlinearities**  
Adds Tanh, GELU, and LayerNorm.  
Explore how different activations behave and why normalization matters in deeper networks.
3. **Learning Signals**  
Adds One-hot Encoding, Cross-Entropy Loss, and Mean Squared Error.  
See how predictions meet targets and how loss becomes a computable, inspectable object.
4. **Beyond Vectors**  
Adds Images, Simple Augmentation, and Flattening.  
Understand how the same matrix-based reasoning extends naturally to visual data.

Hope you enjoy using the Architect—let me know what you think in the comments.

<h2 style="position: relative;font-family: 'SF Pro Display',-apple-system-headline,system-ui,-apple-system,BlinkMacSystemFont,'Segoe UI',Roboto,Helvetica,Arial,sans-serif,'Apple Color Emoji','Segoe UI Emoji','Segoe UI Symbol';font-weight: bold;-webkit-font-smoothing: antialiased;-moz-osx-font-smoothing: antialiased;-webkit-appearance: optimizelegibility;-moz-appearance: optimizelegibility;appearance: optimizelegibility;margin: 1em 0 0.625em 0;color: rgb(54,55,55);line-height: 1.16em;font-size: 1.625em;">Introduction</h2>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">(written by Jubair)</p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">Hi there,</p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>Thank you for your interest in </span><strong>Architect</strong><span>! I’ve been working on this for a long time, and this prototype is implemented entirely within a single Excel workbook.</span></p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>When you open the workbook, you will see two tabs: the </span><strong>Architect</strong><span> tab and the </span><strong>Blueprint</strong><span> tab.</span></p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>For years, Prof. Tom Yeh, my PhD advisor, has been building numerous Excel </span><strong>Blueprints</strong><span> of deep learning architectures entirely by hand. He also forced me and many others students to build blueprints by hand in classes and research projects.</span></p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>I have had enough. So I decided to threaten Prof. Yeh’s job by creating the </span><strong>Architect</strong><span>, a tool that can automatically generate new blueprints. 😉</span></p>
<h4 style="position: relative;font-family: 'SF Pro Display',-apple-system-headline,system-ui,-apple-system,BlinkMacSystemFont,'Segoe UI',Roboto,Helvetica,Arial,sans-serif,'Apple Color Emoji','Segoe UI Emoji','Segoe UI Symbol';font-weight: bold;-webkit-font-smoothing: antialiased;-moz-osx-font-smoothing: antialiased;-webkit-appearance: optimizelegibility;-moz-appearance: optimizelegibility;appearance: optimizelegibility;margin: 1em 0 0.625em 0;color: rgb(54,55,55);line-height: 1.16em;font-size: 1.125em;">Input (Architect)</h4>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>Think of the </span><strong>Architect tab</strong><span> as a planning table. Instead of writing code, you describe your model step by step, one row at a time. Each row answers three basic questions: </span><em>What is the input? What operation should happen? What should come out?</em></p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>The </span><strong>Input column</strong><span> is where tensors are defined. In this example:</span></p>
<pre style="position: relative;background: rgb(238,238,238);padding: 16px;margin: 32px 0;border-radius: 8px;box-sizing: border-box;"><code style="white-space: pre-wrap;font-size: 16px;line-height: 20px;font-weight: 500;"><code style="white-space: pre-wrap;font-size: 16px;line-height: 20px;font-weight: 500;">X = Rand, feat = 6, batch = 10 </code></code></pre>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>It means: create a random input tensor with 6 features and 10 batch elements—we give it a name </span><code>X</code><span>. You don’t need to worry about arrays or indexing—Excel handles that for you.</span></p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>The </span><strong>Ops column</strong><span> describes what to do with that input. You can write—</span></p>
<pre style="position: relative;background: rgb(238,238,238);padding: 16px;margin: 32px 0;border-radius: 8px;box-sizing: border-box;"><code style="white-space: pre-wrap;font-size: 16px;line-height: 20px;font-weight: 500;"><code style="white-space: pre-wrap;font-size: 16px;line-height: 20px;font-weight: 500;">Linear</code></code></pre>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>which means applying a standard linear layer (a matrix multiplication plus bias). This is the same operation used in most neural networks, just written in a human-readable way. In the current version </span><code>(V1)</code><span> available operations are: </span><code>Linear</code><span>, </span><code>ReLU</code><span> and </span><code>Softmax</code><span>.</span></p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>The </span><strong>Output column</strong><span> records what you expect after the operation. We give—</span></p>
<pre style="position: relative;background: rgb(238,238,238);padding: 16px;margin: 32px 0;border-radius: 8px;box-sizing: border-box;"><code style="white-space: pre-wrap;font-size: 16px;line-height: 20px;font-weight: 500;"><code style="white-space: pre-wrap;font-size: 16px;line-height: 20px;font-weight: 500;">X, dim = 5</code></code></pre>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>and it tells The Architect that the Linear layer should map the 6 input features down to 5 output features, producing a new tensor. This will be stored as a variable </span><code>X</code><span>.</span></p>

<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>Once you click </span><strong>Run</strong><span> in the Architect tab, the design is expanded into the </span><strong>Blueprint</strong><span> (see Fig-2). This is where the abstract description turns into something concrete and explorable.</span></p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>At the top of the Blueprint, you see the </span><strong>input tensor</strong><span> laid out as a grid. Each </span><strong>row represents a feature</strong><span>, and each </span><strong>column represents a batch element</strong><span>. This makes the shape of the data immediately visible, without needing to read tensor notation or code.</span></p>

For a Linear layer, the Blueprint shows the </span><strong>weight matrix</strong><span>, the </span><strong>input tensor</strong><span>, and the resulting </span><strong>output tensor</strong><span>, along with the exact math (</span><code>X₀ = W₀X + b₀</code><span>). Every number you see is backed by an </span><strong>Excel formula</strong><span>, so nothing is static or precomputed. You can change a value and watch the effect propagate through the network.</span></p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>On the right side, the </span><strong>Code panel</strong><span> shows the matching </span><strong>PyTorch code</strong><span>, generated layer by layer. This lets you directly connect what you see in the Blueprint with how the same model would be written in practice. The visual blocks and the code blocks stay aligned, making it easy to cross-check understanding.</span></p>

<h2 style="position: relative;font-family: 'SF Pro Display',-apple-system-headline,system-ui,-apple-system,BlinkMacSystemFont,'Segoe UI',Roboto,Helvetica,Arial,sans-serif,'Apple Color Emoji','Segoe UI Emoji','Segoe UI Symbol';font-weight: bold;-webkit-font-smoothing: antialiased;-moz-osx-font-smoothing: antialiased;-webkit-appearance: optimizelegibility;-moz-appearance: optimizelegibility;appearance: optimizelegibility;margin: 1em 0 0.625em 0;color: rgb(54,55,55);line-height: 1.16em;font-size: 1.625em;">Design Philosophy</h2>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">I designed and developed the Architect with a few core requirements that prioritize clarity, familiarity, and learning by doing.</p>
<h4 style="position: relative;font-family: 'SF Pro Display',-apple-system-headline,system-ui,-apple-system,BlinkMacSystemFont,'Segoe UI',Roboto,Helvetica,Arial,sans-serif,'Apple Color Emoji','Segoe UI Emoji','Segoe UI Symbol';font-weight: bold;-webkit-font-smoothing: antialiased;-moz-osx-font-smoothing: antialiased;-webkit-appearance: optimizelegibility;-moz-appearance: optimizelegibility;appearance: optimizelegibility;margin: 1em 0 0.625em 0;color: rgb(54,55,55);line-height: 1.16em;font-size: 1.125em;"><strong>1. Use Excel as the native environment.</strong></h4>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">Excel is already widely known and easy to use. Most users do not need to learn a new interface, language, or tool before they can start exploring neural networks. By running entirely in Excel, the system removes onboarding friction and lets users focus on understanding the model rather than the software.</p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>The Architect is implemented using </span><strong>Office Scripts</strong><span>, which currently run within </span><strong>Microsoft 365 Academic accounts</strong><span>. This means access to an educational Office 365 license is needed to use the system in its current form. For many students and educators, this is already part of their existing setup.</span></p>
<h4 style="position: relative;font-family: 'SF Pro Display',-apple-system-headline,system-ui,-apple-system,BlinkMacSystemFont,'Segoe UI',Roboto,Helvetica,Arial,sans-serif,'Apple Color Emoji','Segoe UI Emoji','Segoe UI Symbol';font-weight: bold;-webkit-font-smoothing: antialiased;-moz-osx-font-smoothing: antialiased;-webkit-appearance: optimizelegibility;-moz-appearance: optimizelegibility;appearance: optimizelegibility;margin: 1em 0 0.625em 0;color: rgb(54,55,55);line-height: 1.16em;font-size: 1.125em;"><strong>2. Make tensor shapes and dimensions visible at all times.</strong></h4>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">Tensor shapes and dimensions must be explicitly shown and easy to track throughout the network. The layout follows a consistent pattern: weights are always placed on the left, and columns consistently represent the batch dimension. This stable visual structure helps users follow the data flow without mentally reconstructing shapes.</p>
<h4 style="position: relative;font-family: 'SF Pro Display',-apple-system-headline,system-ui,-apple-system,BlinkMacSystemFont,'Segoe UI',Roboto,Helvetica,Arial,sans-serif,'Apple Color Emoji','Segoe UI Emoji','Segoe UI Symbol';font-weight: bold;-webkit-font-smoothing: antialiased;-moz-osx-font-smoothing: antialiased;-webkit-appearance: optimizelegibility;-moz-appearance: optimizelegibility;appearance: optimizelegibility;margin: 1em 0 0.625em 0;color: rgb(54,55,55);line-height: 1.16em;font-size: 1.125em;"><strong>3. Reveal the math behind every operation.</strong></h4>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">Each layer exposes its underlying mathematical operation rather than hiding it behind a function name. Combining mathematical formulas with concrete tensors and numbers creates a unique learning experience where users can directly connect equations to actual values.</p>
<h4 style="position: relative;font-family: 'SF Pro Display',-apple-system-headline,system-ui,-apple-system,BlinkMacSystemFont,'Segoe UI',Roboto,Helvetica,Arial,sans-serif,'Apple Color Emoji','Segoe UI Emoji','Segoe UI Symbol';font-weight: bold;-webkit-font-smoothing: antialiased;-moz-osx-font-smoothing: antialiased;-webkit-appearance: optimizelegibility;-moz-appearance: optimizelegibility;appearance: optimizelegibility;margin: 1em 0 0.625em 0;color: rgb(54,55,55);line-height: 1.16em;font-size: 1.125em;"><strong>4. Link visualization directly to PyTorch code.</strong></h4>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">For every visual block, the system provides the corresponding PyTorch code. This allows users to verify the math, tensor operations, and implementation side by side. Seeing the visualization, formulas, and code together makes the overall process easier to understand and trust.</p>
<h4 style="position: relative;font-family: 'SF Pro Display',-apple-system-headline,system-ui,-apple-system,BlinkMacSystemFont,'Segoe UI',Roboto,Helvetica,Arial,sans-serif,'Apple Color Emoji','Segoe UI Emoji','Segoe UI Symbol';font-weight: bold;-webkit-font-smoothing: antialiased;-moz-osx-font-smoothing: antialiased;-webkit-appearance: optimizelegibility;-moz-appearance: optimizelegibility;appearance: optimizelegibility;margin: 1em 0 0.625em 0;color: rgb(54,55,55);line-height: 1.16em;font-size: 1.125em;"><strong>5. Represent tensor values using Excel formulas, not fixed numbers.</strong></h4>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">Tensor entries are expressed as Excel formulas rather than static values. This gives users the freedom to modify inputs, weights, or operations and immediately observe how changes propagate. Users can experiment, play, and align spreadsheet formulas with mathematical expressions in a natural and flexible way.</p>
