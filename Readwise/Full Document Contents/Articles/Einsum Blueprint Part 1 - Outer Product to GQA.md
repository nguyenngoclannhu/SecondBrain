Who is the other Nobel Prize winner whose work quietly powers frontier AI research?

**Albert Einstein**—the physicist who introduced the **Einstein summation convention (einsum)**.

His notation, created over a century ago to simplify tensor equations in physics, is now used intensively in frontier AI labs and open-source implementations around the world to express the core computations behind modern neural networks.

Therefore, not being able to read or write einsum is a form ofilliteracyin frontier AI research.

For example, Albert Gu’s Mamba open-source implementation uses **einsum** extensively. And by the way, if you’ve ever spoken with Albert and were struck by his intelligence like I was, you may wonder who he was named after. When reading his code, for instance, I had trouble reading this line:

```
y = torch.einsum(”bhpn,bn->bhp”, ssm_state.to(dtype), C)
```
Another example, when I studied Grouped Query Attention from Google Research, I encountered this in the source code:

```
similarity = einsum(query, key, “b g h n d, b h s d -> b g h n s”)
```
I felt “illiterate” myself—until I spent considerable time and effort learning how einsum really works.

Over the past few months, I have been building this **Blueprint** to share the approach and insights that helped me master einsum, so others can bridge the same gap between math, code, and intuition.

In **Part 1**, I’ll take you from the most basic concept—the **outer product**—and incrementally build up to **Grouped Query Attention (GQA)**. 

If this Blueprint proves helpful, I plan to create **Part 2**, where we’ll extend these ideas to **Mamba** and one of the latest linear transformer variants.

[![](https://substackcdn.com/image/fetch/$s_!1mz2!,w_1100,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F6d340054-51d4-4143-a8bf-632e8953bb55_978x412.png)](https://substack.com/redirect/10b4e86e-f0fd-4a38-8224-507083973172?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI_zv_M4N2A50pyRXMoP1g)The einsum ‘i,j->ij’ means: take every element of a (indexed by *i*) and multiply it with every element of b (indexed by *j*), keeping both indices in the result. Because neither index repeats, there’s no summation — every combination is preserved. The output is a two-dimensional grid where each cell Y\_ij equals a\_i b\_j. This operation is called the **outer product**, because it expands two 1-D vectors into a full 2-D matrix of all pairwise products.

#### Dot Product

[![](https://substackcdn.com/image/fetch/$s_!4SA-!,w_1100,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F1ab2e8e9-f37f-477e-ba0e-adcb0431f665_978x390.png)](https://substack.com/redirect/63acfe1d-81b8-4a17-adc7-67f452e72120?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI_zv_M4N2A50pyRXMoP1g)The einsum ‘i,i->’ represents the **inner product**, or **dot product**, between two vectors. Each element a\_i is multiplied by the corresponding b\_i, and since the index i doesn’t appear in the output, the products are **summed** into a single scalar. This collapses both axes, producing one value that measures how aligned the two vectors are.

#### Linear Layer (Batch)

[![](https://substackcdn.com/image/fetch/$s_!LVkP!,w_1100,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F17227418-b1da-4dde-99f2-9217d5803d6d_1224x790.png)](https://substack.com/redirect/923475fc-4bbd-4f20-9600-025528adc20a?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI_zv_M4N2A50pyRXMoP1g)When we extend this to processing a **batch** of inputs, the input X gains a new dimension b, representing the batch size. In the math view, each column of X^T corresponds to one sample in the batch. The same weight matrix W^T and bias b^T are applied to all samples. In einsum form, this becomes ‘bd,df->bf’, meaning each input vector in the batch is multiplied by the same weight matrix. The result is a batch of outputs—one per sample—following the same equation y^T=W^T x^T+b^T, just extended across the batch dimension.

<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">Who is the other Nobel Prize winner whose work quietly powers frontier AI research?</p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><strong>Albert Einstein</strong><span>—the physicist who introduced the </span><strong>Einstein summation convention (einsum)</strong><span>.</span></p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">His notation, created over a century ago to simplify tensor equations in physics, is now used intensively in frontier AI labs and open-source implementations around the world to express the core computations behind modern neural networks.</p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>Therefore, not being able to read or write einsum is a form of</span><strong> </strong><span>illiteracy</span><strong> </strong><span>in frontier AI research.</span></p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>For example, Albert Gu’s Mamba open-source implementation uses </span><strong>einsum</strong><span> extensively. And by the way, if you’ve ever spoken with Albert and were struck by his intelligence like I was, you may wonder who he was named after. When reading his code, for instance, I had trouble reading this line:</span></p>
<pre style="position: relative;background: #eeeeee;padding: 16px;margin: 32px 0;border-radius: 8px;box-sizing: border-box;"><code style="white-space: pre-wrap;font-size: 16px;line-height: 20px;font-weight: 500;">y = torch.einsum(”bhpn,bn-&gt;bhp”, ssm\_state.to(dtype), C)</code></pre>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">Another example, when I studied Grouped Query Attention from Google Research, I encountered this in the source code:</p>
<pre style="position: relative;background: #eeeeee;padding: 16px;margin: 32px 0;border-radius: 8px;box-sizing: border-box;"><code style="white-space: pre-wrap;font-size: 16px;line-height: 20px;font-weight: 500;">similarity = einsum(query, key, “b g h n d, b h s d -&gt; b g h n s”)</code></pre>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">I felt “illiterate” myself—until I spent considerable time and effort learning how einsum really works.</p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>Over the past few months, I have been building this </span><strong>Blueprint</strong><span> to share the approach and insights that helped me master einsum, so others can bridge the same gap between math, code, and intuition.</span></p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>In </span><strong>Part 1</strong><span>, I’ll take you from the most basic concept—the </span><strong>outer product</strong><span>—and incrementally build up to </span><strong>Grouped Query Attention (GQA)</strong><span>. </span></p>

<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>The einsum ‘i,j-&gt;ij’ means: take every element of a (indexed by </span><em>i</em><span>) and multiply it with every element of b (indexed by </span><em>j</em><span>), keeping both indices in the result. Because neither index repeats, there’s no summation — every combination is preserved. The output is a two-dimensional grid where each cell Y\_ij equals a\_i b\_j. This operation is called the </span><strong>outer product</strong><span>, because it expands two 1-D vectors into a full 2-D matrix of all pairwise products.</span></p>
<h2 style="position: relative;font-family: 'SF Pro Display',-apple-system-headline,system-ui,-apple-system,BlinkMacSystemFont,'Segoe UI',Roboto,Helvetica,Arial,sans-serif,'Apple Color Emoji','Segoe UI Emoji','Segoe UI Symbol';font-weight: bold;-webkit-font-smoothing: antialiased;-moz-osx-font-smoothing: antialiased;-webkit-appearance: optimizelegibility;-moz-appearance: optimizelegibility;appearance: optimizelegibility;margin: 1em 0 0.625em 0;color: rgb(54,55,55);line-height: 1.16em;font-size: 1.625em;">Dot Product</h2>

<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>The einsum ‘i,i-&gt;’ represents the </span><strong>inner product</strong><span>, or </span><strong>dot product</strong><span>, between two vectors. Each element a\_i is multiplied by the corresponding b\_i, and since the index i doesn’t appear in the output, the products are </span><strong>summed</strong><span> into a single scalar. This collapses both axes, producing one value that measures how aligned the two vectors are.</span></p>

<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>When we extend this to processing a </span><strong>batch</strong><span> of inputs, the input X gains a new dimension b, representing the batch size. In the math view, each column of X^T corresponds to one sample in the batch. The same weight matrix W^T and bias b^T are applied to all samples. In einsum form, this becomes ‘bd,df-&gt;bf’, meaning each input vector in the batch is multiplied by the same weight matrix. The result is a batch of outputs—one per sample—following the same equation y^T=W^T x^T+b^T, just extended across the batch dimension.</span></p>
