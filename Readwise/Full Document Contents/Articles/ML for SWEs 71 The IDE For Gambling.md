A new Y Combinator-backed startup [is releasing a “Brainrot IDE”](https://substack.com/redirect/c1f11d52-5065-4273-a083-a46aa25faaf2?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI_zv_M4N2A50pyRXMoP1g) and, yes, it’s as awful as it sounds. Essentially, this is an IDE that shows brainrot content while a user is waiting for their AI to finish a coding task. If you’re a person, you can already tell how terrible of an idea this is.

Long-time readers of Machine Learning for Software Engineers (*especially* if you were a reader back in the Society’s Backend days!) know how important deep work is for software engineering.

One of the biggest cons of using AI tools for coding is constantly switching between tasks as AI codes for you. There isn’t a way to avoid this as current coding agents have significant latency while reasoning, but there is a huge benefit to limiting it and using time wisely while the AI does its work.

Now, this IDE not only encourages that, but it also exposes you to harmful content in the process. Clad Labs even [shows](https://substack.com/redirect/8101f72b-763a-48c0-9fd1-01c6f70dd431?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI_zv_M4N2A50pyRXMoP1g) ***[gambling](https://substack.com/redirect/8101f72b-763a-48c0-9fd1-01c6f70dd431?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI_zv_M4N2A50pyRXMoP1g)*** as some of the brainrot content in promotional material. Gambling is **never** a good thing and the [state of gambling in the US is abhorrent](https://substack.com/redirect/e4c69307-5018-46da-b59b-6063ecf8ecaa?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI_zv_M4N2A50pyRXMoP1g).

To put it simply, there are 3 things you should know about this IDE:

1. There is no benefit to ingesting brainrot content
2. There is a huge benefit to the critical thinking that occurs while programming.
3. This IDE completely removes the latter to replace it with the former.

#### **You’re Sleeping on Local Models**

I had an argument with Gemini this past week discussing the financial feasibility of using cloud-based infrastructure versus local hardware for model training and inference. I assumed, from my previous research, that cloud infra was always the way to go but Gemini pointed out that for most personal use cases, I’m wrong.

There’s one piece of local hardware worth spending money for local LLM inference: A beefy MacBook or Mac Studio. Not only is it financially feasible, but it also provides other benefits not available from most cloud providers.

Every developer I know that’s using CLI coding tools relies on the quota supplied by the $100+ usage tiers. The most notable tools falling into this category are Claude Code, Cursor, and Codex. Many founders, solopreneurs, and developers find themselves relying on even higher tiers to get their work done at the pace they need to.

So let’s crunch some numbers using the $100/mo figure. Let’s consider the lifespan of a MacBook to be four years at least. This is if you upgrade to stay on the most current hardware.

Four years of paying for a $100/mo subscription ends up being $4800. To upgrade a MacBook purchase to a 128 GB model costs a few thousand dollars. With Apple’s neural engine, which is incredibly efficient for inference, the MacBook can run the highest tier open coding models. These models are on-par or better than the previous generation frontier models and tuned specifically for coding tasks. These open models are incredibly performant.

This means the laptop can run LLM coding agents at less of a cost than cloud infra can provide. This especially true when you consider the lifespan of a MacBook can be well over a decade *and* the next coding models will only become more performant at the same size or smaller and capable of running locally on lesser hardware.

Local models like this also provide a benefit most cloud providers cannot: **reliability.** In discussions about local AI, the primary focus is usually privacy and security. Running an LLM locally also means you don’t have to worry about performance dips when model weights are updated or APIs are throttled. Your model opens updates when *you* update it.

With 128 GB (and definitely 256 GB) of RAM, you can run a 70B+ parameter quantized coding model right on your machine. Many of these open coding models are on-par with or better than the previous generation of top tier models. They nearly replicate the experience of using the CLI tools from large companies (with variance based on user preference, tool usage, etc.).

If this is something that interests you, reach out to me. I’ve purchased a 128 GB RAM MacBook Pro set to arrive today to test this out personally. I’ll be working with these local coding assistants for the next bit and I’ll let you know how it goes.

A while back I wrote an article explaining [why transformer-based LLMs might not get us to AGI](https://substack.com/redirect/42730f8a-e831-4b3d-829c-b1a9688dc352?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI_zv_M4N2A50pyRXMoP1g). These models have very obvious limitations to anyone that uses them or builds products with them. Those limitations inhibit the common definition of AGI. This is why I get so excited about unique AI applications and alternative LLM architectures (looking at you, [state space models](https://substack.com/redirect/742dd918-bcdb-4663-9ae6-f5ab2f5715a5?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI_zv_M4N2A50pyRXMoP1g)).

Yann LeCun has been explaining this for a while, stating that LLMs are a dead end when it comes to achieving AGI. Years ago, he told new AI researchers to focus their efforts elsewhere to help figure out what comes next.

Now, LeCun is putting his money where his mouth is and [starting his own AI lab](https://substack.com/redirect/6919cc77-de19-412f-ae98-d43e8afdee4d?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI_zv_M4N2A50pyRXMoP1g) to research what he thinks is the right direction for more beneficial AI. If you’re involved in AI engineering in any capacity, you should keep an eye on this.

<h2 style="position: relative;font-family: 'SF Pro Display',-apple-system-headline,system-ui,-apple-system,BlinkMacSystemFont,'Segoe UI',Roboto,Helvetica,Arial,sans-serif,'Apple Color Emoji','Segoe UI Emoji','Segoe UI Symbol';font-weight: bold;-webkit-font-smoothing: antialiased;-moz-osx-font-smoothing: antialiased;-webkit-appearance: optimizelegibility;-moz-appearance: optimizelegibility;appearance: optimizelegibility;margin: 1em 0 0.625em 0;color: rgb(54,55,55);line-height: 1.16em;font-size: 1.625em;"><strong>Something That Shouldn’t Exist: An IDE With Gambling Included</strong></h2>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>A new Y Combinator-backed startup </span><a href="https://substack.com/redirect/c1f11d52-5065-4273-a083-a46aa25faaf2?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI\_zv\_M4N2A50pyRXMoP1g" rel="" style="color: #eb5757;text-decoration: none;">is releasing a “Brainrot IDE”</a><span> and, yes, it’s as awful as it sounds. Essentially, this is an IDE that shows brainrot content while a user is waiting for their AI to finish a coding task. If you’re a person, you can already tell how terrible of an idea this is.</span></p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>Long-time readers of Machine Learning for Software Engineers (</span><em>especially</em><span> if you were a reader back in the Society’s Backend days!) know how important deep work is for software engineering.</span></p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">One of the biggest cons of using AI tools for coding is constantly switching between tasks as AI codes for you. There isn’t a way to avoid this as current coding agents have significant latency while reasoning, but there is a huge benefit to limiting it and using time wisely while the AI does its work.</p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>Now, this IDE not only encourages that, but it also exposes you to harmful content in the process. Clad Labs even </span><a href="https://substack.com/redirect/8101f72b-763a-48c0-9fd1-01c6f70dd431?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI\_zv\_M4N2A50pyRXMoP1g" rel="" style="color: #eb5757;text-decoration: none;">shows </a><em><strong><a href="https://substack.com/redirect/8101f72b-763a-48c0-9fd1-01c6f70dd431?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI\_zv\_M4N2A50pyRXMoP1g" rel="" style="color: #eb5757;text-decoration: none;">gambling</a></strong></em><span> as some of the brainrot content in promotional material. Gambling is </span><strong>never </strong><span>a good thing and the </span><a href="https://substack.com/redirect/e4c69307-5018-46da-b59b-6063ecf8ecaa?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI\_zv\_M4N2A50pyRXMoP1g" rel="" style="color: #eb5757;text-decoration: none;">state of gambling in the US is abhorrent</a><span>.</span></p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">To put it simply, there are 3 things you should know about this IDE:</p>
<ol style="margin-top: 0;padding: 0;">
<li style="margin: 8px 0 0 32px;"><p style="color: rgb(54,55,55);line-height: 26px;margin-bottom: 0;box-sizing: border-box;padding-left: 4px;font-size: 16px;margin: 0;">There is no benefit to ingesting brainrot content</p></li>
<li style="margin: 8px 0 0 32px;"><p style="color: rgb(54,55,55);line-height: 26px;margin-bottom: 0;box-sizing: border-box;padding-left: 4px;font-size: 16px;margin: 0;">There is a huge benefit to the critical thinking that occurs while programming.</p></li>
<li style="margin: 8px 0 0 32px;"><p style="color: rgb(54,55,55);line-height: 26px;margin-bottom: 0;box-sizing: border-box;padding-left: 4px;font-size: 16px;margin: 0;">This IDE completely removes the latter to replace it with the former.</p></li>
</ol>
<h2 style="position: relative;font-family: 'SF Pro Display',-apple-system-headline,system-ui,-apple-system,BlinkMacSystemFont,'Segoe UI',Roboto,Helvetica,Arial,sans-serif,'Apple Color Emoji','Segoe UI Emoji','Segoe UI Symbol';font-weight: bold;-webkit-font-smoothing: antialiased;-moz-osx-font-smoothing: antialiased;-webkit-appearance: optimizelegibility;-moz-appearance: optimizelegibility;appearance: optimizelegibility;margin: 1em 0 0.625em 0;color: rgb(54,55,55);line-height: 1.16em;font-size: 1.625em;"><strong>You’re Sleeping on Local Models</strong></h2>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">I had an argument with Gemini this past week discussing the financial feasibility of using cloud-based infrastructure versus local hardware for model training and inference. I assumed, from my previous research, that cloud infra was always the way to go but Gemini pointed out that for most personal use cases, I’m wrong.</p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">There’s one piece of local hardware worth spending money for local LLM inference: A beefy MacBook or Mac Studio. Not only is it financially feasible, but it also provides other benefits not available from most cloud providers.</p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">Every developer I know that’s using CLI coding tools relies on the quota supplied by the $100+ usage tiers. The most notable tools falling into this category are Claude Code, Cursor, and Codex. Many founders, solopreneurs, and developers find themselves relying on even higher tiers to get their work done at the pace they need to.</p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">So let’s crunch some numbers using the $100/mo figure. Let’s consider the lifespan of a MacBook to be four years at least. This is if you upgrade to stay on the most current hardware.</p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">Four years of paying for a $100/mo subscription ends up being $4800. To upgrade a MacBook purchase to a 128 GB model costs a few thousand dollars. With Apple’s neural engine, which is incredibly efficient for inference, the MacBook can run the highest tier open coding models. These models are on-par or better than the previous generation frontier models and tuned specifically for coding tasks. These open models are incredibly performant.</p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>This means the laptop can run LLM coding agents at less of a cost than cloud infra can provide. This especially true when you consider the lifespan of a MacBook can be well over a decade </span><em>and</em><span> the next coding models will only become more performant at the same size or smaller and capable of running locally on lesser hardware.</span></p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>Local models like this also provide a benefit most cloud providers cannot: </span><strong>reliability. </strong><span>In discussions about local AI, the primary focus is usually privacy and security. Running an LLM locally also means you don’t have to worry about performance dips when model weights are updated or APIs are throttled. Your model opens updates when </span><em>you</em><span> update it.</span></p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">With 128 GB (and definitely 256 GB) of RAM, you can run a 70B+ parameter quantized coding model right on your machine. Many of these open coding models are on-par with or better than the previous generation of top tier models. They nearly replicate the experience of using the CLI tools from large companies (with variance based on user preference, tool usage, etc.).</p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">If this is something that interests you, reach out to me. I’ve purchased a 128 GB RAM MacBook Pro set to arrive today to test this out personally. I’ll be working with these local coding assistants for the next bit and I’ll let you know how it goes.</p>

<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>A while back I wrote an article explaining </span><a href="https://substack.com/redirect/42730f8a-e831-4b3d-829c-b1a9688dc352?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI\_zv\_M4N2A50pyRXMoP1g" rel="" style="color: #eb5757;text-decoration: none;">why transformer-based LLMs might not get us to AGI</a><span>. This is why I get so excited about unique AI applications and alternative LLM architectures (looking at you, </span><a href="https://substack.com/redirect/742dd918-bcdb-4663-9ae6-f5ab2f5715a5?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI\_zv\_M4N2A50pyRXMoP1g" rel="" style="color: #eb5757;text-decoration: none;">state space models</a><span>).</span></p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">Yann LeCun has been explaining this for a while, stating that LLMs are a dead end when it comes to achieving AGI. Years ago, he told new AI researchers to focus their efforts elsewhere to help figure out what comes next.</p>
<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;"><span>Now, LeCun is putting his money where his mouth is and </span><a href="https://substack.com/redirect/6919cc77-de19-412f-ae98-d43e8afdee4d?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI\_zv\_M4N2A50pyRXMoP1g" rel="" style="color: #eb5757;text-decoration: none;">starting his own AI lab</a><span> to research what he thinks is the right direction for more beneficial AI. If you’re involved in AI engineering in any capacity, you should keep an eye on this.</span></p>
