# [PyTorch/Excel] Sinusoidal Positional Encoding

![rw-book-cover](https://readwise-assets.s3.amazonaws.com/static/images/article1.be68295a7e40.png)

- Author: [[Prof. Tom Yeh - AI by Hand ✍️]]
- Full Title: [PyTorch/Excel] Sinusoidal Positional Encoding
- Category: #articles
- Summary: Sinusoidal positional encoding helps models understand the order of tokens by adding sine and cosine signals to each token's embedding. This encoding allows the model to know both the exact position and the distance between tokens without extra learned parameters. It is commonly added to token embeddings before attention layers in Transformers to give the model position information.

#### Purpose

Sinusoidal positional encoding gives a model a sense of token order in architectures that process all tokens in parallel. By adding sine and cosine signals of different frequencies to each token embedding, it encodes both absolute position and relative distance between tokens. This allows the model to reason about sequence order (e.g., “next” or “farther away”) and generalize to longer sequences without learning position-specific parameters.

[![](https://substackcdn.com/image/fetch/$s_!nDdo!,w_1100,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F5f05e827-c1c0-4bc9-9640-cbb43b8c47a6_926x826.png)](https://substack.com/redirect/af7ce253-9bc9-4071-9516-46bdfccd7492?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI_zv_M4N2A50pyRXMoP1g)#### Calculation

For each token position, we compute a positional encoding vector using sine and cosine functions at different frequencies. Even-indexed rows (dimensions) use a sine function, while odd-indexed rows use a cosine function, both scaled by a power of 10,000 so that each dimension varies at a different rate.

[![](https://substackcdn.com/image/fetch/$s_!5QkS!,w_1100,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F7f5bffdb-ab51-449d-a38a-5425c5c41852_844x1080.png)](https://substack.com/redirect/56d46cdb-a20a-4493-b905-f34b8b08358c?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI_zv_M4N2A50pyRXMoP1g)#### Application

The most common use of sinusoidal positional encoding in a Transformer is to add it directly to the token embeddings before they are fed into the attention layers. Token embeddings capture what each token is, while the sinusoidal signals encode where each token appears in the sequence. By summing the two vectors element-wise, the model receives both content and position information in a single representation, allowing attention to reason about order and relative distance without changing the Transformer’s architecture or adding learned positional parameters.

[![](https://substackcdn.com/image/fetch/$s_!vCRe!,w_1100,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Fea05cb23-b5cd-4a1b-a2ba-2c978b1da861_1200x916.png)](https://substack.com/redirect/e9cded5a-6bc3-4408-9d0a-e8187ba03a19?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI_zv_M4N2A50pyRXMoP1g)For example, if the token embedding vectors at positions 4, 5, and 6 are identical, the Transformer has no way to distinguish their order on its own. After adding sinusoidal positional encodings, each embedding is shifted by a slightly different positional vector, making the representations distinct. Importantly, these shifts are smooth and structured, so the overall geometry of the embedding space is preserved while position information is injected.

[![](https://substackcdn.com/image/fetch/$s_!gCCO!,w_1100,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F8a712ac6-5438-463a-8744-50ff49d3de3f_584x1302.png)](https://substack.com/redirect/735c85a7-9a7e-40e9-84cc-246dce5838f2?j=eyJ1IjoiNnE2ZWdsIn0.JeUaI03hkTZe3g0Y-WbKcpI_zv_M4N2A50pyRXMoP1g)#### Excel Emulation of PyTorch Code

```
1	import torch
2	seq_len = 10
3	d_model = 16
4	
5	pe = torch.zeros(d_model, seq_len)
6	position = torch.arange(seq_len)                
7	dim_index = torch.arange(0, d_model, 2)
8	scale = -math.log(10000.0) / d_model
9	div_term = torch.exp(dim_index * scale)
10	angles = div_term[:, None] * position[None, :]  
11	
12	# even dimensions ↓ (sine)
13	even = torch.sin(angles)
14	# odd dimensions ↑ (cosine)
15	odd = torch.cos(angles)
16	
17	pe[0::2, :] = even
18	pe[1::2, :] = odd
```

<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">Sinusoidal positional encoding gives a model a sense of token order in architectures that process all tokens in parallel. By adding sine and cosine signals of different frequencies to each token embedding, it encodes both absolute position and relative distance between tokens. This allows the model to reason about sequence order (e.g., “next” or “farther away”) and generalize to longer sequences without learning position-specific parameters.</p>

<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">For each token position, we compute a positional encoding vector using sine and cosine functions at different frequencies. Even-indexed rows (dimensions) use a sine function, while odd-indexed rows use a cosine function, both scaled by a power of 10,000 so that each dimension varies at a different rate.</p>

<p style="margin: 0 0 20px 0;color: rgb(54,55,55);line-height: 26px;font-size: 16px;">The most common use of sinusoidal positional encoding in a Transformer is to add it directly to the token embeddings before they are fed into the attention layers. Token embeddings capture what each token is, while the sinusoidal signals encode where each token appears in the sequence. By summing the two vectors element-wise, the model receives both content and position information in a single representation, allowing attention to reason about order and relative distance without changing the Transformer’s architecture or adding learned positional parameters.</p>
